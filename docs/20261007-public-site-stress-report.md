# NOUR 公网全站性能与只读压测报告

**测试日期：** 2026-10-07  
**公网：** https://xn--dqry4os3s3gb.com/  
**测试性质：** 生产环境有界、低速、只读压测；未执行 AI 生成、登录、支付、充值、解锁、写入、TTS、媒体转码或全文整库下载。

## 结论摘要

- 纯站内只读基线：**230/230 请求通过**，其中 226 个 HTTP 200，4 个预期的校验型 HTTP 400；未出现 5xx、网络超时或受保护响应。
- 全量目录：**8,794/8,794 条**成功分页读取，唯一 ID **8,794**，缺 ID **0**，缺标题 **0**；其中可读 **8,756**，元数据/官方入口型 **38**。
- 服务稳定性：`nur.service` 与 `nur-health-monitor.service` 均保持 active，压测期间 `NRestarts=0`。
- 需要单独处理的异常：`/api/nodes` 在独立探测中 3 次均达到 30 秒读超时，并伴随第三方订阅源 404 日志。它会等待外部源，不应与站内 API 延迟混为一谈；本报告的 230 请求纯站内基线已排除该路由。
- 当前真正影响用户体感的慢路径是首页/内容聚合：浏览器仍请求约 **960 KB** 的 `/api/sentences`，`/api/home_stats` 也在约 1.2 秒量级。

两种视口均无 JavaScript 错误。浏览器层资源传输约为：手机 **1.545 MB / 38 个同源资源**，桌面 **1.607 MB / 40 个同源资源**。

### 3.1 当前加载瓶颈

阶段 7 的静态按需策略已经把 6 个大数据脚本移出 HTML 初始标签；当前基线显示这些按需资源合计约 **2.884 MB gzip**，并且已带 immutable 缓存。它们不会全部在 HTML 首屏脚本标签中直接加载。

但真实首页运行时仍出现以下慢资源：

- `/api/sentences`：约 **960 KB**，手机耗时约 **3.588 秒**，桌面约 **2.077 秒**。
- `/api/home_stats`：手机约 **2.803 秒**，桌面约 **1.525 秒**。
- 手机还观察到四学派、经典索引与书目池并行请求，延迟受同一单进程竞争影响。

因此，下一轮不应继续盲目拆静态脚本，而应优先减少首页实际 API payload 和并发聚合工作。

## 4. 服务器资源与异常

压测期间远端资源采样：

- CPU：单次峰值 busy **100%**，user 峰值 91%，system 峰值 41%；说明 6 req/s 已能让单核 Python 服务出现短时 CPU 饱和。
- 内存：vmstat 记录的最低 free 约 **641 MB**；压测结束时主机约 3.65 GB 总内存、2.15 GB available、Swap 2 GB 中约 336 MB 已占用。
- Swap：仅 1 个采样点出现 swap in/out（各 15 页），未见持续 Swap 风暴。
- 运行队列：最大 10；blocked 进程 0。
- 服务：`nur.service=active`、`nur-health-monitor.service=active`、重启次数 0。
- 日志：纯站内压测窗口内未见 OOM、Traceback、5xx 或服务重启；外部节点探测窗口可见第三方订阅源 404。

### `/api/nodes` 的单独结论

完整旧探测列表中 `/api/nodes` 3 次均在约 30 秒超时，并在服务日志中触发失效的外部订阅 URL 404。该接口当前表现为“请求线程等待外部源”，不是普通内存/目录 API 慢。建议后续：

1. 外部源抓取与 HTTP 请求解耦，使用后台刷新或短 TTL 缓存；
2. 外部源单源超时控制在 1–2 秒，并立即返回上一份缓存/空结果；
3. 页面展示“外部源暂不可用”，不要让 `/api/nodes` 阻塞整页或健康监控。

本轮没有直接修改该业务路径，仅在压测工具中增加可选跳过开关。

## 5. 建议的下一轮优化顺序

### P0：隔离 `/api/nodes` 外部源

先解决请求阻塞和 404 日志污染，保证这个接口即使外部源失效也能在 1–2 秒内返回可解释结果。

### P1：首页句子接口瘦身

首页只需要今日一句，应把 `/api/sentences` 的全量读取改成有界摘要/单句接口；点击进入句子库时再按需分页加载全文句子。目标是将首页传输从约 960 KB 降到几十 KB 以内。

### P1：优化首页统计与聚合

为无敏感信息的首页统计加入 15–30 秒短 TTL 缓存，或者把可公开统计与用户个人进度分开请求，避免首屏等待。

### P2：收敛 `/api/books` 与 `/api/vocab`

默认只返回首页需要的摘要字段，完整内容改为分页/按需；保持旧字段和旧入口兼容。

### P2：建立性能门槛

建议下轮验收使用：普通站内 API p95 ≤ 500 ms；首页首屏不请求全量句子/词汇；`/api/nodes` 外部源不可用时仍 ≤ 2 秒返回；手机/桌面核心路由切换 ≤ 1 秒，学习工作台的额外数据应并行或延后加载。
