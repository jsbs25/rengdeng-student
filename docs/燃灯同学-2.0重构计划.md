# 燃灯同学 2.0 重构计划

**扫描日期：** 2026-10-05  
**扫描范围：** 当前 `arabic-learning` 项目、生成 HTML、`server.py`、`data/`、`app/`、`deploy/`、测试工具与既有发布文档。  
**本次状态：** 只完成扫描与计划，未按本计划修改业务代码。

---

## 0. 重要结论

当前项目不是 FastAPI 项目，而是：

```text
浏览器 / PWA / Expo App
        ↓
静态单页 arabic_learning.html
        ↓
Python 标准库 ThreadingHTTPServer
        ↓
本地数据、按需书库、词典、语音、DeepSeek API
```

当前生产服务：

```text
systemd nur.service
ExecStart=/usr/bin/python3 /opt/nur/server.py
监听：8080
反向代理：Nginx / HTTPS
```

当前 `deploy/requirements.txt` 只有可选的 `faster-whisper` 说明，没有 FastAPI、Uvicorn 或 OpenAI SDK 依赖。

**因此第一阶段不迁移到 FastAPI，不重写后端，不更换技术栈。**

附件中的：

```text
frontend/ + backend/main.py + backend/ai.py + FastAPI/Uvicorn
```

作为未来可能的逻辑分层参考保留，但不能直接落地为技术栈迁移。若未来确实需要拆分，也必须先做兼容适配层、保留原 `/api/*` 路径和旧服务回滚路线，并单独确认。

## 5. 旧功能 → 2.0 页面映射

附件期望的一级导航是：**首页 / 阅读 / 词典 / 学习 / 我的**。

这和当前 NOUR 的“首页 / 书库 / NOUR AI / 我的”不完全相同。为避免突然破坏用户习惯，计划采用兼容式映射：

| 2.0 一级入口 | 内容主体 | 现有能力复用 | 第一阶段是否显示 |
|---|---|---|---|
| 首页 | 今日继续、导读、今日句子、学习进度、推荐阅读 | 阅读足迹、统计、真实目录、句子和学习记录 | 是 |
| 阅读 | 书库、最近阅读、收藏、经典、六大部、古兰经、法学与原文阅读 | `nav('learn')`、目录 API、Shamela、OpenITI | 是 |
| 词典 | 查词、词根/词形、本地释义、例句、发音、生词 | `openDict()`、`/api/dict/*`、生词本 | 是 |
| 学习 | 对话、句子、语法、词法、闪卡、挑战、听力、跟读、学习进度 | 现有模块与本地数据 | 是 |
| 我的 | 阅读记录、生词本、收藏、主题、设置、数据导入导出、账户与会员 | `renderMe()`、localStorage、账户 API | 是 |

“阅读”可以继续沿用当前书库命名“书库”作为中文显示，是否最终改成“阅读”在第一轮视觉原型中确认；底层 `nav('learn')` 不改。

## 6. 目标产品结构

### 6.1 首页

首屏只保留五个核心区域：

1. 今日继续
2. 导读
3. 今日一句阿拉伯语
4. 我的学习进度
5. 推荐阅读

约束：

- 不在首页默认打开大聊天框。
- 不展示几十个功能入口。
- 书目、统计和推荐必须来自真实数据。
- AI 只以“解释 / 导读 / 问燃灯”等自然文案出现，不把 AI 三个字写满整页。
- “你今天想读什么？”可以连接现有全局搜索和真实目录；第一版不做无法核验的全网自动建书。

### 6.2 阅读器

阅读器是 2.0 的核心页面：

- 中央正文：阿拉伯语 RTL，中文辅助 LTR。
- 选词后出现轻量词卡：词义、词根、词性、发音、例句、收藏。
- “问燃灯”作为用户主动打开的上下文工具，不使用巨大常驻聊天框。
- 当前书、章节、页、段落、选句和用户语言偏好进入上下文。
- 页级讲解、学派比较、经文/圣训证据和站内回链放在侧栏或底部抽屉。
- 手机沉浸式，桌面可形成书库 / 正文 / 上下文三栏。
- 不改 OpenITI 分段、Shamela 真实全文、断点缓存和页级 AI API。

### 6.3 词典

词典页不重复复制数据：

- 本地词典优先。
- 需要时使用现有有界网络补充。
- 阅读器选词直接复用同一词卡。
- 词根、词形和语法分析是用户主动操作，不默认弹出大 AI 对话。

### 6.4 学习

把已有功能收拢为学习路径：

- 日常对话
- 句子
- 语法与词法
- 字母
- 闪卡与生词复习
- 闯关和测验
- 听力、诵读、跟读
- 学习进度与每日目标

现有数据和函数不删除，只减少第一层入口数量。

### 6.5 我的

统一承载：

- 生词本
- 收藏和书签
- 阅读历史
- 学习数据
- 外观与阅读偏好
- 数据导入导出
- 登录、会员和额度
- 音频偏好与语音设置

## 7. 分阶段实施计划

严格遵守“每次只修改一个模块”。每一步都先本地构建、手机/桌面回归，再决定是否发布。

### 阶段 0：保护性基线，不改业务

**目标：** 建立功能清单、接口快照、数据摘要和回归门槛。

计划产物：

- 页面/入口清单
- API 路由清单
- 受保护数据清单
- 现有 localStorage 键快照
- 生成 HTML 的构建校验
- 核心路径冒烟测试

验收：

- `/api/catalog/meta` 仍为 8,794。
- Shamela 8220 仍为 239 页。
- OpenITI 流式回归通过。
- 古兰经、词典、选词、生词、AI、语音、主题和账户入口可打开。

### 阶段 1：一级导航适配层

**只改：** `data/nour-product-shell.js`、对应 CSS 和构建注入。  
**不改：** 后端、数据、阅读器业务函数。

内容：

- 建立首页 / 阅读 / 词典 / 学习 / 我的五入口。
- 继续保留旧 `nav('learn')`、`nav('me')` 和页面节点。
- 搜索改成全局快捷入口。
- AI 改成“问燃灯”二级入口，不删除 `#aiSec`。

验收：

- 手机底部导航不遮挡正文。
- 桌面导航可到达书库、阅读器、词典和个人页。
- 旧入口函数仍可直接调用。

### 阶段 2：首页层级重排

**只改：首页展示层和首页 CSS。**

内容：

- 首屏只保留五个核心区域。
- 继续阅读读取真实足迹。
- 推荐阅读读取真实索引。
- 今日一句读取已有句子数据。
- 学习进度读取已有记录。

验收：

- 首屏不出现假数据。
- 首页不默认展开 AI 聊天。

## 9. 对附件技术图的处理决定

附件顶部的 FastAPI 结构可以保留为**目标逻辑分层图**：

```text
前端请求
  → Python API 适配层
  → AI / 书库 / 词典 / 学习服务
  → 用户学习记录 + 内容库
  → 上下文学习大脑
```

但当前实施不直接创建 `backend/main.py`、不安装 FastAPI/Uvicorn、不迁移 `server.py`，理由：

1. 用户明确要求不得擅自更换项目技术栈。
2. 现有 `server.py` 承载账户、支付、会员、AI、阅读、目录、音频和运维功能，直接拆分风险很高。
3. 生产 systemd、Nginx、监控和回滚都围绕 `server.py` 工作。
4. 现有生成 HTML 依赖大量全局函数和内联脚本，后端框架迁移不能自动解决前端兼容问题。
5. FastAPI 本身不会解决 AI 上下文、数据治理或界面层级问题。

如果未来确实需要模块化，建议在阶段 8 之后另立项目：

- 先抽取纯 Python service 函数，不改 HTTP 路由。
- 给旧 `/api/*` 加适配测试。
- 新旧服务并行运行，只读影子流量。
- 通过完整公网回归后，再讨论是否使用 Uvicorn。
