### 1.2 当前架构的问题（真实、按严重度排）

| # | 问题 | 影响 | 严重度 |
|---|---|---|---|
| 1 | **数据存 JSON 文件**（codes/users/payments/pricing…） | 并发写会丢数据；无法多端同步；查询要全量读入内存 | 🔴 高 |
| 2 | **单文件前端 1.4MB**（含 40万+ 字数据内联） | 首屏慢（国内手机明显）；改一处要重新构建全站 | 🟠 中高 |
| 3 | **三份拷贝**（z.html / app.html / app2.html） | 改了一处忘同步 → 版本不一致（已踩过坑） | 🟠 中 |
| 4 | **Cloudflare 按路径缓存**静态资源 | 改了 CSS/JS 不生效，必须换文件名 | 🟠 中 |
| 5 | **AI 依赖单一外部 API（DeepSeek）** | 官方涨价/限流/封号 → 全站 AI 停摆 | 🟠 中 |
| 6 | **无向量检索**（AI 不知道你 2 万句语料） | AI 回答靠通用知识，无法"根据我的资料回答" | 🔴 高（本方案核心要解决） |
| 7 | **无用户体系**（只有 device_id） | 无法做注册/配额/统计（商业化前置） | 🟡 中低 |
| 8 | **服务器 1核 3.6GB** | 跑不了任何模型；也不能跑向量库（勉强可） | 🟠 中 |

> ⚠️ 结论：**你现在的 AI 是"借来的"**（调 DeepSeek）✗
> 要变成"属于自己的"，核心不是换模型 ✓ 而是 **建立你自己的知识库（RAG）+ 自己的 API 层** ✓

## 3. AI 架构（推荐：RAG 优先的"三层"架构）

### 3.1 目标形态

```
你的网页 / iPhone / iPad / Android
              ↓  （带 API Key）
   ┌──────────────────────────────────────┐
   │  你自己的 API 层  api.你的域名.com     │
   │   /v1/chat /v1/words /v1/sentences    │
   │   /v1/lessons /v1/search              │
   │   · 鉴权 · 限流 · 用量统计 · 日志      │
   └──────────────┬───────────────────────┘
                  ↓
   ┌──────────────────────────────────────┐
   │  知识层（RAG）—— 这是"属于你"的关键    │
   │   2.1万句 + 9.1万词 + 295词义 + 对话   │
   │   ↓ 切分 → Embedding → 向量库          │
   │   ↓ 检索 Top-K → 拼进 Prompt           │
   └──────────────┬───────────────────────┘
                  ↓
   ┌──────────────────────────────────────┐
   │  模型层（可换，随时替换，不锁死）      │
   │   阶段1：DeepSeek API（便宜、现成）    │
   │   阶段2：本地 Qwen2.5-7B / silma-9B   │
   │   阶段3：你自己 LoRA 微调的专有模型    │
   └──────────────────────────────────────┘
```

**核心思想**：**模型可以换，知识库和 API 是你自己的** ✓
今天用 DeepSeek ✓ 明天换本地模型 ✓ 你的数据、接口、用户都不会丢 ✓

### 3.2 为什么这样设计

| 理由 | 说明 |
|---|---|
| 你的服务器跑不了模型 | 1核/3.6GB/无GPU ✗ 模型必须在别处（API 或你的 Mac） |
| RAG 让 AI"知道"你的资料 | 检索到 2.1 万句/9.1 万词再交给模型 → 答案有据可查 |
| 不锁死模型 | 以后 DeepSeek 涨价/停服 → 换一个就行，前端不用改 |
| 成本极低 | 向量库用 SQLite 文件 ✓ 不需额外服务器 ✓ |

## 6. RAG 方案（免费 / 开源 / 低成本）

### 6.1 流程

```
你的资料（句子 / 词汇 / 词义 / 对话）
      ↓ ① 清洗（去重 · 去无中文 · 去宗教）
      ↓ ② 切分（按条目切；长文本 300~500 字）
      ↓ ③ Embedding（本地模型，免费）
      ↓ ④ 存入向量库（SQLite 文件，零成本）
      ↓ ⑤ 检索 Top-K（用户提问时）
      ↓ ⑥ 拼进 Prompt → 交给模型
      ↓ ⑦ 返回答案（附"依据哪条资料"）
```

### 6.2 技术选型（全部免费/开源）

| 环节 | 选型 | 理由 |
|---|---|---|
| Embedding | `BAAI/bge-small-zh-v1.5`（100MB）或 `bge-m3`（多语言 2GB） | 本地跑 ✗ 不花钱 ✓ bge-m3 中阿英通吃 ✓ |
| **向量库** | **SQLite + sqlite-vec** | ✅ 单文件 ✓ 无需服务器 ✓ 你 1 核机器也跑得动 ✓ |
| 备选 | FAISS（内存索引） | 语料小更快 ✓ 重启要重建 |
| 检索 | 向量 + **BM25 关键词混合** | 阿语拼写敏感 ✓ 纯向量会漏 ✓ |
| 重排（可选） | bge-reranker-base | 提准确率 ✓ 第二阶段加 |

### 6.3 关键设计：资料可增量

```bash
# 以后加一本教材：
python3 ragbuild.py --add data/kb/新教材.pdf
# → 自动 切分 → 向量化 → 入库 ✓ 不用重启服务 ✓
```

### 6.4 向量规模估算（实测推算）

```
21,238 句 × ≈30 token  → 64 万 token
91,000 词 × ≈15 token  → 137 万 token
────────────────────────────────────
合计 ≈ 200 万 token
bge-m3（1024 维 · fp16）→ 索引 ≈ 4GB
bge-small（512 维）      → 索引 ≈ 1GB  ✓ 推荐
```
→ **完全放得进一个 SQLite 文件 ✓ 零服务器成本 ✓**

## 7. 微调方案（LoRA · 第二阶段）

### 7.1 什么时候才该微调

- ✅ **该做**：RAG 上线后，"答对了但风格不像老师" → 用 LoRA 调**表达风格**
- ❌ **不该做**：想用它"灌知识" → 那是 RAG 的活；微调灌知识效果差且易遗忘

### 7.2 自动数据生成流水线

```
原始资料（21,238 句 · 295 词义）
   ↓ 清洗（去重 / 去宗教 / 去空）
   ↓ 去重（三份重复合并为一份）
   ↓ 格式统一（a / cn / root / src 字段）
   ↓ 生成 instruction / input / output
   ↓ 质量检查（规则 + AI 交叉验证 + 人工抽检 5%）
   ↓ train / val 切分（95:5）
   ↓ 训练集 JSONL
```

**样本示例**：
```json
{"instruction":"解释阿拉伯语单词 كِتَاب","input":"","output":"كِتَاب 是阳性名词，意为「书」。词根 ك-ت-ب 与「书写」相关；复数 كُتُب。例句：هَذَا كِتَابٌ جَدِيدٌ（这是一本新书）。","source":"vocab_meanings.json#295","type":"from_original"}
{"instruction":"把「我想学习阿拉伯语」翻译成阿拉伯语","input":"","output":"أُرِيدُ أَنْ أَتَعَلَّمَ اللُّغَةَ الْعَرَبِيَّةَ","source":"builtin_sentences.js#12043","type":"from_original"}
{"instruction":"用「مَدْرَسَة（学校）」造一个初级例句","input":"","output":"أَذْهَبُ إِلَى الْمَدْرَسَةِ كُلَّ يَوْمٍ（我每天去学校）","source":"model_generated","verified":false}
```

> ⚠️ **严格区分两类数据**（符合你的要求）
> · `type:"from_original"` → 来自你的原始资料 ✓ **可信** ✓
> · `type:"model_generated"` → AI 生成 ✓ **必须人工抽检** ✓ 不得对外称"权威" ✓
> · 涉及宗教内容 → **一律保留 `src` 出处** ✓ 且**不混入模型生成内容** ✓

### 7.3 LoRA 配置建议

| 参数 | 建议 | 说明 |
|---|---|---|
| 基础模型 | Qwen2.5-7B-Instruct | Apache-2.0 ✓ 可商用 |
| 方法 | **QLoRA（4bit）** | 16GB 内存能跑 |
| rank (r) | 16 | 数据量小 → 别太大 |
| alpha | 32 | = 2r |
| target_modules | q/k/v/o_proj | 标准 |
| lr | 2e-4 | QLoRA 常用 |
| epochs | 3 | >3 会过拟合 |
| batch | 1 + 梯度累积 16 | M2 内存限制 |
| 数据量 | **建议 ≥1,000 条**（现只有 295，需扩充） |
