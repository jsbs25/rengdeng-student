# NOUR 页级 AI 导读性能记录（2026-10-03）

## 结论

当前页级导读的实际默认模型是 **DeepSeek `deepseek-flash`**，不是普通聊天使用的 `deepseek-chat`。生产请求配置为：

- 官方端点：`api.deepseek.com/chat/completions`
- `response_format: json_object`
- `thinking: disabled`
- 页文本上限：6,500 字符
- 生产输出上限：1,150 tokens
- 请求超时：75 秒
- 失败后才兼容重试 `deepseek-chat`；JSON 无法解析时才走一次 700-token 紧凑修复请求
- 页级分析按内容、书目、学派、页码和响应语言缓存；缓存命中不产生新的模型 token

本次 Flash 实测使用与生产相同的页级 prompt builder、JSON mode、thinking disabled 和 1,150-token 上限，样本是代表性阿拉伯语复杂语法/法学文本，不写入模型返回正文，也不是长期 SLA 或质量保证。

| 样本 | 输入文本 | Prompt | Prompt tokens | Completion tokens | Total tokens | 延迟 | JSON | 修复请求 |
|---|---:|---:|---:|---:|---:|---:|---|---:|
| Flash 短复杂页 | 1,100 字符 | 2,677 字符 | 1,266 | 758 | 2,024 | 4,169 ms | 通过 | 0 |
| Flash 长复杂页 | 6,500 字符 | 8,077 字符 | 3,341 | 1,025 | 4,366 | 6,316 ms | 通过 | 0 |

既有受控 `deepseek-chat` 阿语基准（不同 prompt，不能与上表直接作为 SLA 对比）记录为：短 1,902 ms / 360 tokens，中 1,948 ms / 773 tokens，长 1,795 ms / 2,373 tokens。两组测试的网络时间、prompt 和输出上限不同，不能仅凭这组数字宣称一个模型全面优于另一个模型。

## 工程判断

- 长页增加了约 2,075 prompt tokens，并在这次样本中比短页多约 2.1 秒；延迟随输入和结构化输出增加，但仍明显低于 75 秒超时。
- 长页输出达到 1,025 tokens，接近 1,150 上限；若继续压缩输出字段，可能损失四学派比较、证据状态和语言说明的完整性。
- 两次 Flash 返回都能直接解析 JSON，生产修复请求没有被触发。若未来出现格式失败，第二次 700-token 修复会增加一次网络往返和额外 token，不能把失败重试当成“零成本”。
- 本次没有调用 `deepseek-v4-pro`：用户要求控制额外调用次数，而当前目标是审计线上默认 Flash 路径；没有形成 pro 的质量对照，不能声称 pro 更准确或更快。

## 已保留的保守优化边界

1. 继续使用页级缓存和并发 claim，避免同一页重复请求。
2. 普通语言页面可以在未来单独采用更短的输出 schema；法学、古兰经学、圣训学页面保留证据状态、学派比较和核验提示，不自动升级到 pro。
3. 不降低当前 6,500 字符页文本上限，不为了追求表面速度截断阿拉伯词法/句法上下文。
4. 只在结构化 JSON 真的不可解析时使用一次紧凑修复；修复失败不写入成功缓存，也不把空结果伪装成讲解。
5. 若要做正式模型选型，应在同一批脱敏页面、同一 prompt、同一 max_tokens 下分别测多轮，并增加人工质量评审；本记录不替代该评审。

## 数据与权限边界

基准脚本只读取本地 AI key，不打印、不写入 key；报告只保存聚合指标。正文阅读仍通过现有 OpenITI/Shamela 按需路径，页级 AI 结果只作学习辅助，不能替代原典核验、合格学者意见或现实法特瓦。
