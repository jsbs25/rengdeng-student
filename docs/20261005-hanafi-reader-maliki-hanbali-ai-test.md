### 最慢条目复测

为避免把一次网络/浏览器调度抖动误判为稳定回归，单独复测了 `البناية` 407：

- 手机：API 2,375 ms，首次打开 3,478 ms；7,019 页仍完整返回。
- 桌面：API 5,296 ms，首次打开 6,371 ms；7,019 页仍完整返回。
- 复测首、中、末页索引均可达，JavaScript 错误为 0。

桌面复测比首次运行更慢，说明主要瓶颈是网络响应与大 JSONL 页面数组传输，不是翻页渲染。正文加载完成后，翻页只更新 `RD_PAGE`，不会为每一页重新请求整本正文；首次运行的章节切换稳定约 74–98 ms。

### 结论

- **《الهداية》4404：加载良好。** 1,246 页首开约 1.18–1.60 秒，适合作为四学派阅读室的即时示范书。
- **《المبسوط》1852：功能完整，但大书首开明显较慢。** 6,278 页公网首开约 4.54–6.43 秒。
- **《البناية》407：功能完整，但三部中负载最大。** 7,019 页首开约 4.36–6.37 秒，适合保留现有“首次载入提示”，不适合把所有页面预加载到手机端可见 DOM。
- **稳定性：** 三部书均能到达末页，没有 413、空正文或 JavaScript 错误。
- **优化方向：** 下一轮若要进一步提速，应改为 Shamela 页级 Range/分页 API 或压缩传输，而不是改变书目映射；当前前端切页已经不是主要瓶颈。

## 三、NOUR AI：`المصالح المرسلة` 马立克—汉百里横向比较

### 测试方式

在本地启动与生产相同的 `server.py`，使用真实 `/api/chat/message` 路由发送一次 `fast=true` 请求。loopback 只用于绕过用户额度检查；仍然调用项目当前 DeepSeek 路径、系统提示与复杂问题 3,200 token 预算。没有重复请求，没有联网查资料分支，没有修改用户会话或生产数据。

**测试延迟：** 18,411 ms  
**回答长度：** 5,724 字符  
**HTTP：** 200

### 结构检查

| 检查项 | 结果 |
|---|---|
| 覆盖马立克 / `المالكية` | 通过 |
| 覆盖汉百里 / `الحنابلة` | 通过 |
| 正面解释 `المصالح المرسلة` 与公共利益 | 通过 |
| 讨论经文、圣训、共识、类比、教法目的等证据层级 | 通过 |
| 区分原典、后世学派总结、模型归纳 | 通过 |
| 未核验卷页、经训编号、作者原话标记“待核验” | 通过 |
| 非复述式回答，长度超过 500 字符 | 通过 |
| 现实个案法特瓦 | 未提供 |

### 输出质量观察

回答形成了比较清楚的主线：

- **马立克传统：** 将 `المصالح المرسلة` 作为较明确的法源学论证类型讨论，强调它不能违背明确文本或确定共识，也不能只是个人偏好。
- **汉百里传统：** 指出相近问题更常通过 `الاستصلاح`、`سد الذرائع`、`الضرورة`、`السياسة الشرعية` 和 `المقاصد` 等复合框架表达，而不一定把它单独固定为同名法源。
- **共同点：** 公共利益不能任意推翻明确 `نص`，必要性和防止危害必须受到范围限制。
- **证据边界：** 回答明确把具体作者、卷页、经文编号、圣训编号和作者原话标为待核验，并提示模型归纳不等于逐字引文。

### 需要继续核验的地方

这次 AI 结果通过结构质量检查，但不应直接当作学术引证。尤其需要回到实际版本核验：

- `الموافقات` 中沙提比对 `المصلحة`、`المقاصد` 的具体章节与措辞；
- `المدونة الكبرى`、`الموطأ` 中能否直接支持某个具体马立克法学结论；
- `إعلام الموقعين`、`الطرق الحكمية` 中伊本·盖伊姆关于利益、目的和政策性推理的原文；
- `السياسة الشرعية`、`سد الذرائع` 与 `المصالح المرسلة` 之间的术语边界；
- 模型回答中列出的“法源顺序”属于概括性模型归纳，不能当作四派固定、无争议的排序。

回答中有一处方法性提醒值得保留：不能因为教材常把 `المصالح المرسلة` 说成马立克特色，就把汉百里所有公共利益论证都排除在外；同样不能因为两派都谈 `مصلحة`，就把它们的术语地位和证据机制说成完全相同。
